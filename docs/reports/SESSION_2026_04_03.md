# Technical Session Report: Optimized Agent Kinematics & Unified State Architecture
**Date:** 2026-04-03  
**Category:** Architectural Refinement / Kinematic Synchronization  
**Status:** Completed & Validated

## 1. Abstract
This session focused on resolving performance bottlenecks and kinematic synchronization errors within the `UE5BetterSim` digital twin framework. The primary outcome was the implementation of the `ARoboSimAgent` C++ base class in Unreal Engine 5, which introduces O(1) joint component lookups via hash-mapping and a relative-transform application layer. Additionally, the Zenoh bridge was refactored to support unified agent state payloads, significantly reducing network overhead and ensuring atomic synchronization of mobile agent base-frames and joints.

## 2. Methodology & Implementation

### 2.1 Host (UE5/C++): `ARoboSimAgent`
The legacy Blueprint-based string-matching logic for joint updates was replaced by a high-performance C++ base class (`ARoboSimAgent`).
- **Optimization:** Implemented `TMap<FString, USceneComponent*> JointsCache` to store component references during initialization, eliminating expensive `GetChildComponent` calls during the 60Hz physics update loop.
- **Structural Integrity:** Introduced `InitialTransformsCache` to store the rest pose of every actuated joint. Kinematic updates from MuJoCo are now applied as relative rotations/translations to these rest poses, preventing the "model collapse" bug associated with absolute coordinate overrides.
- **Automation:** Added automatic Actor Tag assignment (`Simulate`, `Agent`, `Mobile`/`Bolted`) based on the `bIsMobile` property.

### 2.2 Guest (MuJoCo/Python): Unified State Bridge
The `BridgeManager` was refactored to align with the updated `sim/agent/{name}/state` contract.
- **Protocol Optimization:** Implemented joint-name prefix stripping (removing `AgentName_`) before transmission, reducing JSON payload size.
- **Synchronization:** Integrated `root_transform` (6DOF base-frame data) into the specific agent state payload, ensuring that mobile agents update their global position and internal joints in a single network packet.

### 2.3 Bridge (Zenoh 1.7.2)
- **Data Contract:** Formalized the `root_transform` schema in `rules/common/json-contract.md`.

## 3. Architectural Justification
The shift to relative-transform application is critical for digital twin fidelity. Absolute coordinate overrides in UE5 often fail to account for baked offsets in the glTF/URDF import process. By caching the rest-pose and applying deltas, we maintain a 1:1 mapping with MuJoCo's generalized coordinates while respecting UE5's scene hierarchy. The unification of the agent state payload minimizes the probability of base-frame/joint desynchronization, which is a requirement for high-fidelity VR teleoperation.

## 4. Testing & Validation
- **Validation Sequence:** 
  1. Bootstrapped Guest backend with `substeps=2` for reduced latency.
  2. Initialized Host world export; verified `RoboSim_Telemetry.log` correctly identified and cached 70+ joints across multiple agents (Unitree G1, Franka FR3, Kuka IIWA14).
  3. Verified mobile base-frame tracking for `Unitree G1` via the new unified payload.
- **Results:** Sub-3ms RTT maintained. Zero syntax errors or runtime crashes observed in the final iteration.
